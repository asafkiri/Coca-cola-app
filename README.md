# מחירים ושלטים לתעודות קוקה־קולה

אפליקציה סטטית בעברית: קריאת PDF מקורי מהספק, מחיר סופי לאריזת ספק והכנת שלטי מבצע. כל תעודה עצמאית. אין Firebase, מסד נתונים, מפתח AI או העלאת תעודות לשרת.

## שימוש

1. בוחרים PDF מקורי של תעודת אספקה. כל עמודי אותה תעודה צריכים להיות בקובץ אחד, כולל הסיכום הכספי.
2. האפליקציה קוראת את טבלת ההתחשבנות ומאמתת אותה מול סיכום המסמך ומפרט האספקה, כאשר הוא זמין.
3. רואים מחיר סופי לארגז/אריזת הספק. פתיחת הפירוט מציגה את כל רכיבי החישוב.
4. בוחרים מוצרים לשלטים נפרדים או לשלט משותף. בכל מוצר מזינים ידנית מספר בקבוקים באריזת ספק אחת. הכמות אינה נשמרת בקטלוג.
5. בוחרים מחיר לבקבוק, כמות במחיר או אחוז הנחה, ואפשר להחיל המלצה לפי תוספת הרווח הרצויה.
6. משתפים PNG או מדפיסים/שומרים PDF באמצעות הדפדפן, 1/2/4 שלטים בדף.

רק שם החנות ואחוז ברירת המחדל נשמרים מקומית בדפדפן. התעודה והשלטים בזיכרון עד רענון או סגירה; אין היסטוריה או סנכרון בין מכשירים. התעודות המקוריות ונתוני העסק אינם חלק מהמאגר.

## כללי חישוב

- כספים מהמסמך מפוענחים לאגורות שלמות; עלות לארגז/לבקבוק נשמרת כשבר מדויק באמצעות BigInt עד להצגה.
- לכל שורה: **סחורה + סכום הנחה חתום + ערך אריזה + מס קנייה + פיקדון = סכום שורה לפני מע״מ**. ההנחה בתעודה שלילית.
- אחוז ההנחה נבדק מול הסחורה בלבד. המחיר כפול הכמות נבדק מול סכום הסחורה. מותרת אגורה אחת בשל עיגול נתוני התצוגה בשתי בדיקות אלה בלבד. סכום הרכיבים וסיכומי העמודות חייבים להתאים בדיוק.
- המחיר כולל המע״מ מבוסס על **סכום השורה הסופי**, ולכן לא מנכים שוב הנחה ולא מוסיפים שוב פיקדון/אריזה/מס קנייה.
- המע״מ נקרא מהתעודה. לא מניחים שהוא 18%, וגם 0 חייב להופיע במפורש.
- מחיר אריזה = סכום השורה לפני מע״מ × (1 + שיעור מע״מ) ÷ מספר אריזות הספק.
- הפרש עיגול של המסמך מוצג בנפרד; לא מחלקים אותו שרירותית בין המוצרים. המע״מ הכולל נבדק על סכום המסמך לאחר הפרש העיגול. מחירי שורה/אריזה מוצגים מעוגלים, ולכן סכימתם ידנית עשויה להיות שונה באגורות.
- המלצות משתמשות ב**תוספת על העלות**, כמו עורך השלטים הפנימיים בייטבתה. אין זו רווחיות מתוך מחיר המכירה.
- בסיס התוספת הוא הסחורה לאחר הנחה ועוד מס קנייה. פיקדון וערך אריזה מצטרפים פעם אחת, בלי תוספת רווח. הכול מוכפל בשיעור המע״מ שנקרא. זו הצעת תמחור; רווחי החנות נטו אינם מחושבים.
- מחיר מבצע מומלץ = [(סחורה נטו + מס קנייה) × (1 + תוספת רווח) + פיקדון + אריזה] × (1 + מע״מ) ÷ כמות אריזות ÷ בקבוקים באריזה × כמות במבצע.
- אין עיגול ביניים של מחיר הארגז או הבקבוק. המחיר המומלץ מעוגל בסוף כלפי מעלה לאגורה, או לסיומת .90 אם נבחרה. בניגוד לעיגול הישן בייטבתה, לא מעגלים מתחת לתוספת שהתבקשה. אפשר להקליד מחיר אחר ולראות את התוספת בפועל.
- בשלט משותף מחשבים לכל מוצר בנפרד ובוחרים את ההמלצה הגבוהה ביותר. מוצגת התוספת בפועל הנמוכה ביותר בקבוצה.
- מבצע אחוזים מחושב על מחיר המכירה הרגיל ללא פיקדון/אריזה; החיובים האלה אינם מוזלים. אחוז ההנחה לצרכן אינו נלקח אוטומטית מהנחת הספק.

## תמיכה ומגבלות

תומך בפורמט הדיגיטלי שנבדק של החברה המרכזית להפצת משקאות: טבלת "מפרט התחשבנות" עם כל עמודות המחיר וסיכום כספי. פענוח העמודות נעשה לפי מיקום הכותרות ולא לפי סדר מילים ב־PDF. פורמט אחר, צילום, מסמך חסר, תעודת זיכוי או טבלת החזרות לא ריקה נעצרים עם הסבר; אין ניחוש של מחירים או OCR. שינוי בפורמט הספק עשוי לחייב עדכון קוד. אימות חשבוני בודק את העקביות הפנימית של התעודה, לא את נכונות המחירים שסוכמו עם הספק.

## פיתוח ופרסום

אין תהליך build. GitHub Pages מוגדר לפרסום `main` מתיקיית `/ (root)`. כל הנתיבים יחסיים, כך שהאפליקציה פועלת תחת `/Coca-cola-app/`.

```sh
python3 -m http.server 8765
npm test
```

בדיקות המספרים רצות ב־Node ללא התקנת תלויות. PDF.js **5.6.205** מוטמע ב־`vendor/` כדי לא לשלוח קבצים ל־CDN ולא להיות תלויים בגרסה משתנה. הרישיון שלו נמצא לידו. רק הגרסה המורחבת לתאימות דפדפנים ו־worker לקריאת PDF נכללים; אין ניתוח באמצעות קוד PDF מוטמע (`isEvalSupported: false`).

בבדיקה עם מסמך אמיתי יש לשמור את הקובץ מחוץ למאגר. `.gitignore` חוסם PDF, תמונות ונתוני בדיקה מקומיים. אין להוסיף מסמכי לקוח או פרטים אישיים להיסטוריית git.
